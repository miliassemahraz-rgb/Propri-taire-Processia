# WP-01 : Socle du monorepo, outillage, CI, docker compose, documentation

- Statut : terminé (2026-11-26), directement sur `main`.
- Spécification : `docs/specs/increment-1.md`, section 7, WP-01.

## Ce qui a été fait

- **Monorepo** pnpm 10 (workspaces `apps/*`, `packages/*`, `e2e`) et Turborepo (`build`, `typecheck`, `dev`). Versions exactes figées (`save-exact`, `pnpm-lock.yaml`). ADR 0001.
- **`packages/config`** : tsconfig (`base`, `library`, `nest`, `next`), configuration ESLint (`@processia/config/eslint`), Prettier, schéma zod des variables d'environnement (`@processia/config/env`, `loadEnv()`), et les tests associés. L'ESLint inclut :
  - les frontières entre paquets (matrice dans `eslint/boundaries.mjs`, test d'absence de cycle) ;
  - `i18next/no-literal-string` (`jsx-only`) sur `apps/web` et `packages/ui` ;
  - `jsx-a11y`, les règles Next.js, `typescript-eslint`, `consistent-type-imports`.
- **`apps/web`** : Next.js 16 (App Router), page d'accueil en français affichant « Processia » via `@processia/i18n`, `lang="fr"`, proxy `/api/*` vers l'API (vérifié : `/api/health` renvoie `{"db":"ok","s3":"ok"}`).
- **`apps/api`** : NestJS 11. `GET /health` interroge PostgreSQL (`SELECT 1`) et les deux buckets S3 (`HeadBucket`) et renvoie `{db,s3}` ; réponse 503 avec le détail si une dépendance échoue. `worker.ts` est un point d'entrée vide (valide l'environnement et reste en vie).
- **`apps/collab`** : serveur Hocuspocus minimal (sans authentification ni persistance), avec un test qui démarre le serveur sur un port libre.
- **Paquets** `model`, `policy`, `contracts`, `db`, `ai`, `ingest`, `bpmn`, `diagnostic`, `exports`, `ui`, `test-fixtures` : `index.ts` et un test chacun (`i18n` contient les messages `fr.json` et la fonction `t` typée). `db` a un script `db:migrate` de remplacement.
- **Tests** : Vitest à la racine (alias vers les sources) ; `pnpm test:int` (`*.int.test.ts`, services requis) ; Playwright dans `e2e/` avec un test de fumée (titre « Processia », `lang`, axe-core WCAG 2 A/AA sans violation `serious` ou `critical`).
- **`docker-compose.yml`** : postgres:17 (bases `processia` et `processia_test`), minio avec création des deux buckets privés (`minio-init`), mailpit ; tous déclarés sains (`up -d --wait`). Profil `apps` : api, collab, web avec des `Dockerfile.dev`.
- **`.env.example`**, **`.github/workflows/ci.yml`** (installation, lint, typecheck, tests unitaires, services compose, tests d'intégration, build, E2E de fumée, `actionlint`).
- **Documentation** : `CLAUDE.md`, `docs/wp/TRACKER.md` (26 WP), `docs/dev/CONVENTIONS.md`, `docs/dev/RUNBOOK.md`, `docs/po/DECISIONS.md` (PO-1 à PO-24, statut « en attente »), ADR 0001 à 0010 et modèle 0000.

**Non exécuté** : la construction des images du profil `apps` (`docker compose --profile apps build`). Elle échoue dans cet environnement : le proxy sortant intercepte TLS et le conteneur de build ne fait pas confiance à son certificat (Corepack ne peut pas télécharger pnpm, `SELF_SIGNED_CERT_IN_CHAIN`). Seule la validité du fichier a été vérifiée (`docker compose config`). Les Dockerfiles ne sont donc pas éprouvés ; le premier agent qui dispose d'un réseau direct doit lancer le build.

## Écarts par rapport à la spécification

1. **Node 22 au lieu de Node 24 LTS** (spécification 1.2) : l'environnement fourni a Node 22. `engines >=22.12`, `.nvmrc` = 22, images `node:22-alpine`. Le passage à 24 est mécanique (ADR 0001).
2. **Image MinIO** : `minio/minio` et `minio/mc` n'existent plus sur Docker Hub et `quay.io` est inaccessible depuis l'environnement. `docker-compose.yml` utilise `pgsty/minio` (fork communautaire, `mc` inclus), version fixée, avec la variable `MINIO_IMAGE` pour revenir à `quay.io/minio/minio`. L'image officielle n'a pas pu être testée. À confirmer par le PO (propriété de la chaîne d'approvisionnement).
3. **Frontières par `no-restricted-imports`** et non par `eslint-plugin-boundaries` ni `dependency-cruiser` : choix permis par la spécification (« ou ») ; pas de dépendance à la résolution de modules. Vérifié : un import `@processia/ai` depuis `apps/web` ou `packages/model`, et un import relatif entre paquets, échouent bien.
4. **`minio-init` ne se termine pas** (il crée les buckets puis reste en vie avec un contrôle de santé) : `docker compose up --wait` échoue si un service sort, même avec le code 0.
5. **`packages/i18n`** : les messages sont dans `packages/i18n/src/messages/fr.json` (et non `packages/i18n/messages/`) pour rester sous le `rootDir` de `tsc`. La fonction `t` est minimale ; le choix d'une bibliothèque (next-intl) est laissé à WP-07.
6. **ESLint 9** (et non 10) : `eslint-plugin-i18next` ne déclare pas encore ESLint 10 ; pnpm affiche un avertissement de dépréciation.
7. **Pas de contrôle `dependency-cruiser`** en plus d'ESLint.
8. **`pnpm db:migrate`** est un script de remplacement qui affiche un message (le schéma arrive avec WP-04). `pnpm db:reset` fonctionne : `docker compose down -v`, `up --wait`, puis `db:migrate`.
9. La **bibliothèque de tests de l'API** n'émet pas les métadonnées de décorateurs (esbuild) : les tests unitaires de l'API instancient les classes à la main. WP-04 et suivants peuvent ajouter `unplugin-swc` si des tests Nest complets sont nécessaires.
10. Versions : TypeScript 5.9, ESLint 9.39, NestJS 11, Vitest 3.2, Hocuspocus 3.4, Next.js 16.4, Playwright 1.65, zod 4. Des majeures plus récentes existent (TypeScript 7, Vitest 5, NestJS 12, ESLint 10) et n'ont pas été adoptées pour limiter le risque ; la montée de version est un chantier à part.

## Dettes

- Images `Dockerfile.dev` non éprouvées (voir plus haut). Elles copient le dépôt dans l'image : pas de rechargement à chaud en conteneur.
- Le workflow CI n'a pas été exécuté sur GitHub. Points à surveiller au premier passage : `pnpm/action-setup@v4` (lit `packageManager`), téléchargement de l'image MinIO, `playwright install --with-deps`.
- Pas de scan de dépendances ni de dependabot (hors périmètre ; WP-25).
