## Ce qui a été fait

`packages/ai` :

- **Pipelines** `extraction.chunk` (`ExtractionCandidates` : candidats de type métier, acteur, activité macro / processus / tâche, outil, terme ; chacun avec `chunkId`, `quote` ou `rationale`) et `reconcile` (`ReconcileResult` : `matches`, `merges`, `discrepancies`), avec prompts `extraction.chunk.fr.md` et `reconcile.fr.md`, schémas zod et contrôles sémantiques (`pipelines/extraction.ts`). `extraction.document_visual` existait (WP-11) ; son scénario du pilote est ajouté.
- **Code déterministe** (`extraction/`) : `text.ts` (normalisation NFC, casse, apostrophes, guillemets, tirets, espaces ; `verifyCitation` renvoie `charStart` / `charEnd` dans le texte d'origine), `candidates.ts` (vérification et rétrogradation, fusion des doublons, résumé du modèle, rapprochement avec le modèle existant, résolution des parents), `plan.ts` (entrée de `reconcile`, intégration de sa réponse), `changeset.ts` (conversion en ChangeSet `extraction` : éléments `extracted` ou `hypothesis`, jamais `confirmed`, identifiants `tmp:n`, corroboration des éléments existants, éléments `discrepancy`, compteurs).

`packages/test-fixtures` : `pilot.ts`, le scénario factice du pilote. La description du pilote (`PILOT_DESCRIPTION`) reprend le CDC 8.1 à 8.5 sous forme de notes de consultant (secteur et métier, 14 paragraphes de macroprocessus avec activités et couverture, 8 acteurs, 4 parties prenantes, workflow, objectifs). Les données (`PILOT_MACROS`, `PILOT_ACTORS`, `PILOT_STAKEHOLDERS`) produisent à la fois le texte et les citations. Un second document contradictoire (`PILOT_CONTRADICTORY_DOCUMENT`, aussi sous forme de PDF scanné `PILOT_SCANNED_DOCUMENT_NAME`) attribue les relances clients au collaborateur comptable alors que la description les attribue à l'assistant administratif. Les trois scénarios (`PILOT_SCENARIOS`) sont de vraies fonctions de la requête.

`packages/contracts` : `startExtractionSchema`, `StartExtractionResult`, `ExtractionSummary`, `RunDto.resultVersion`.

`apps/api` (`AnalysisModule`) :

- `ExtractionService` : file `analysis.extraction` (`JOB_QUEUES`), consommateur déclaré dans `onModuleInit`, qui enregistre aussi les scénarios du pilote auprès du fournisseur factice. Déroulé : lecture des morceaux sous RLS, `extraction.chunk` par morceau (résumé du modèle et des candidats précédents), vérification des citations contre `source_chunks.text`, fusion, rapprochement, `reconcile` si le modèle n'est pas vide, ChangeSet, `ModelService.commit(…, { actor: 'ai', aiCallId })` avec reprise sur `STALE`. La progression est diffusée par `run.progress` ; l'exécution (`analysis_runs`, kind `extraction`) reçoit `result_version` ; la notification `analysis.extraction_done` porte les compteurs, `analysis.failed` l'erreur.
- Route `POST /missions/:id/analysis/extractions` (`model.edit`), corps `{ sourceId? }` : sans `sourceId`, la description est figée (« Analyser », `SourcesService.freezeDescription`) puis analysée ; réponse `{ runId, source }` ; 409 `CONFLICT` (`ANALYSIS_IN_PROGRESS`) si une extraction est déjà en cours. Suivi par `GET runs/:runId`.
- Pas de migration.

## Écarts et choix

1. **Aucun enchaînement automatique après le dépôt d'un document** : l'extraction se demande explicitement ([PO-80]).
2. **Origine d'un candidat rétrogradé ou inféré** : `ai_knowledge`, sans référence ([PO-81]) ; la spécification demande seulement la rétrogradation et la justification.
3. **Réextraction** : rapprochement déterministe par type et libellé (ADR 0017), corroboration des éléments non décidés, aucune promotion d'hypothèse ([PO-82]). `reconcile` n'est pas appelé quand le modèle est vide (rien à réconcilier) ; il l'est à chaque réextraction suivante (journalisé).
4. **Écarts** : seul le cas « deux responsables différents pour la même activité » est détecté par le scénario factice ; le prompt de `reconcile` est général ([PO-83]).
5. **`macroCategory` non renseigné** ([PO-84]) ; `execution` vaut `manual` ; `fieldProvenance` non utilisé.
6. **Compteur de qualité** (spécification 4.5, « dans `ai_calls` ») : le journal `ai_calls` est en écriture seule pour la couche IA (WP-09) ; le compteur `citationsDemoted` est porté par la notification `analysis.extraction_done` et par le retour de l'exécution, pas par la ligne `ai_calls`.
7. **Lien source vers exécution** : `analysis_runs` n'a pas de `source_id` ; le message `run.progress` porte `sourceId`, la notification aussi.
8. **Outils, termes du glossaire** : pris en charge par le schéma des candidats (et testés dans le cas pur) ; le pilote ne produit que deux outils (logiciels comptable et de paie). Les règles, objets de données, indicateurs et flux ne sont pas extraits à l'incrément 1 de ce pipeline (ils viennent de `answer.integrate` et `process.flow`, WP-14 et WP-17).

## Dettes

- Rapprochement par libellé exact : les synonymes ne sont rapprochés que par `reconcile` (IA réelle). Pas de fusion manuelle côté API (WP-13).
- Pas de découpage de la réponse d'un morceau très dense (plafond 400 candidats par morceau, 16 000 jetons de sortie).
- Les enregistrements exacts (`AI_RECORD=1`) du pilote ne sont pas livrés (aucune clé) ; le scénario scripté en tient lieu.
- `reconcile` reçoit le résumé complet du modèle (non filtré par pertinence).
- Le temps de traitement n'est pas borné par morceau (un morceau en erreur fait échouer l'exécution entière, sans écriture partielle).

## Suite : ce que les prochains WP doivent savoir

- **WP-13 (interface Analyse)** : lancer par `POST /missions/:id/analysis/extractions` (corps `{}` pour « Analyser », ou `{ sourceId }` pour un document déjà lisible) ; suivre `run.progress` (`kind: 'extraction'`) ou `GET runs/:runId` (`resultVersion`) ; messages à traduire : 409 `CONFLICT` avec `details.reason = 'ANALYSIS_IN_PROGRESS'`, 400 pour une description vide ou une source non lisible, notifications `analysis.extraction_done` (compteurs `ExtractionSummary`) et `analysis.failed`. Les éléments à afficher viennent de `GET model` : `status.value` (`extracted`, `hypothesis`), `provenance.refs` (visionneuse : `GET sources/:id/chunks/:ordinal?charStart&charEnd` avec `chunkId` de la référence, retrouvé par la liste des morceaux), éléments `discrepancy` ouverts (`sides[].refs`, `elementIds`). La résolution d'un écart (champ `resolution`) et la confirmation relèvent de l'interface.
- **WP-14 (questionnement)** : `answer.integrate` peut réutiliser `extractionChunkPipeline`, `verifyChunkCandidates`, `matchExisting`, `buildExtractionChangeSet` (cause `answer`, source `kind: 'answer'` créée par `createTextSource`) : seul le `cause` du ChangeSet change. Même schéma de candidats.
- **WP-17 (enchaînements)** : les 14 macroprocessus et leurs processus existent avec `scope` ; les liens du niveau 0 (`process_link`), le workflow du CDC 8.4 et les responsables ne sont pas extraits. Le CDC 8.4 est en traits `specificity`. `PILOT_DESCRIPTION` peut servir de base aux scénarios `process.flow`.
- **Fusion** : `docs/po/DECISIONS.md` reçoit PO-80 à PO-84 en fin de tableau ; relancer `pnpm exec prettier --write docs/po/DECISIONS.md` après fusion si les largeurs de colonnes divergent.
