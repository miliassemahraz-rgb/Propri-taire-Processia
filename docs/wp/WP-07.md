## Ce qui a été fait

- **`packages/ui`** (React Aria Components, ADR 0010) : `Button`, `TextField` (libellé, aide, erreur), `Select`, `Checkbox`, `Dialog` (modal, focus piégé, Échap), `PopoverPanel` (centre de notifications), `Tabs`, `DataTable` (légende, région défilable au clavier), `StatusBadge`, `ProgressMeter` (`progressbar` annoncée), `SegmentedControl`, `Notice`, `ToastHost` / `showToast`, `SkipLink`. Thème dans `styles.css` (jetons de la charte : fond #F6F7F9, accent #1F4FBF, succès, avertissement, erreur ; cibles de 44 px ; focus visible ; contrastes AA). La feuille est copiée dans `dist/` par le build et importée par la mise en page racine.
- **`packages/i18n`** : tous les textes de l'application dans `fr.json` (navigation, formulaires, tableaux, tableau de bord, administration) et **un message en français pour chacun des 22 codes d'erreur de l'API**, plus `NETWORK` et `UNKNOWN` ; avertissements de capacité (`CAPABILITY_MISSING`) par capacité. Choix : pas de `next-intl` (ADR 0018). La règle `no-literal-string` exclut désormais les seuls attributs techniques (`packages/config/eslint/index.mjs`).
- **`apps/web`** :
  - Mise en page : lien d'évitement, navigation latérale (Missions ; Administration pour l'administrateur), sélecteur mode simple / expert, nom et rôle de l'utilisateur, déconnexion, centre de notifications (vide) ; en-tête de mission (client, nom, étape, « lecture seule » si `myRole` est nul), bandeau « IA simulée » et sous-navigation de mission. `lang="fr"`, titre unique par page (« Titre · Processia »), page « introuvable ».
  - Client API typé (`lib/api.ts`, `lib/endpoints.ts`) validé par les schémas de `@processia/contracts`, jeton CSRF rejoué sur les requêtes non GET, erreurs traduites (`lib/errors.ts`).
  - Pages : `/connexion`, `/connexion/verification` (code TOTP ou code de secours), `/connexion/enrolement` (QR, clé manuelle, 10 codes de secours affichés une fois), `/invitations/[token]`, `/missions` (liste selon la maquette : étape, jauge de complétude, rôle ; création dans un dialogue avec avertissements de capacité), `/missions/[id]` (tableau de bord : étapes, complétude par concept dépliable avec ce qui manque, à faire, activité récente vide ; mode expert : version de tête et client), `/missions/[id]/equipe` (membres, affectation, retrait, invitation dans la mission), `/administration/utilisateurs` (liste, invitation, déverrouillage, désactivation), `/administration/clients`, `/administration/ia` (configuration par client, onglets configuration et politique de données, clé masquée, acceptation de la politique, avertissements de capacité).
- **API (deux routes d'appui, hors liste de WP-06, ADR 0019)** : `GET /missions/:id/ai-status` (`{ simulated }`, tout membre) et `GET /missions/:id/assignable-users` (`mission.assign`) ; contrats `aiStatusSchema` et `assignableUserSchema` ; tests d'intégration dans `missions.int.test.ts`.
- **Outillage** : `pnpm e2e` construit le web et l'API, `packages/db` gagne `e2e:prepare` (base `processia_test` remise à l'état du seed), Playwright démarre l'API sur cette base puis le web ; un seul travailleur. `docs/maquettes` est exclu de Prettier (sources de référence, format « Design Component »).

## Écarts et choix

1. **Pas de `next-intl`** : fonction `t` typée conservée (ADR 0018).
2. **Deux routes d'API ajoutées** (bandeau « IA simulée », liste des comptes affectables) : le web ne pouvait pas les obtenir autrement sans élargir les droits [PO-90], [PO-92].
3. **Navigation** : les entrées Analyse, Cartographie, Diagnostic et Portail du validateur de la maquette ne sont pas affichées tant que leurs pages n'existent pas (sinon liens morts) [PO-93]. Le tableau de bord n'a pas de lien « Examiner / Répondre / Voir ».
4. **Complétude par concept** : calculée dans le navigateur avec `completeness()` de `@processia/model` sur la tête du modèle (`GET /missions/:id/model`) ; le validateur n'y a pas accès (403), le tableau de bord le dit.
5. **Polices** : Inter et Space Grotesk sont nommées dans la pile CSS mais non chargées (pas de service tiers) ; elles retombent sur la police système [ADR 0019].
6. **Tailles et accès** : `DataTable` expose une région focalisable (`tabindex`) pour le défilement au clavier ; l'exception `jsx-a11y/no-noninteractive-tabindex` est commentée sur place.
7. **E2E** : un seul travailleur, base `processia_test` ; le test de navigation au clavier attend le pas TOTP suivant (≈ 30 s) car le serveur refuse le rejeu d'un code ; l'API démarrée par Playwright exige que le port 3001 soit libre.
8. `docs/maquettes` ajouté à `.prettierignore` : les maquettes livrées avec le commit PO-17 faisaient échouer `prettier --check`.

## Dettes

- Pas de test de rendu des composants `packages/ui` hors navigateur (pas de jsdom dans le dépôt) : ils sont couverts par les parcours Playwright et axe-core.
- Les pluriels sont écrits « hypothèse(s) » (voir ADR 0018).
- Pas de pagination des listes (missions, utilisateurs), comme côté API.
- `GET /me` est appelé à chaque chargement complet de page ; la session expirée n'est détectée qu'à l'appel suivant (le client renvoie alors `UNAUTHENTICATED`, affiché mais sans redirection automatique hors du chargement initial).
- Le contrôle de rôle global (`admin`, `mission_manager`) pour afficher « Nouvelle mission » est écrit dans le web : `packages/policy` n'est pas autorisé côté web (frontières). La garde de l'API fait foi.
- Capture d'écran : se régénère avec `E2E_SCREENSHOT=1 pnpm e2e` (test `dashboard.spec.ts`).

## Suite : ce que WP-10 et WP-13 doivent savoir

- Ajouter une page de mission : `apps/web/src/app/(app)/missions/[missionId]/<chemin>/page.tsx` (composant serveur mince avec `metadata.title` unique, qui monte un composant client) ; ajouter l'entrée dans `components/mission-frame.tsx` (`links`). `useMission()` donne le `MissionSummary` (`myRole`, `phase`, `progress`, `headVersion`) ; `useMode()` le mode simple / expert ; `endpoints` et `errorMessage` pour l'API ; `showToast` pour les confirmations.
- **Titre de page** : `metadata.title` seul (le gabarit « · Processia » est ajouté). Chaque page nouvelle doit avoir son test axe (`expectNoSeriousViolations` dans `e2e/tests/support.ts`) et son titre ajouté au test d'unicité.
- **Texte** : tout texte passe par `fr.json` ; une erreur d'API a déjà son message (`errors.*`) ; un nouveau code d'erreur doit être ajouté à `ERROR_MESSAGE_KEYS` (le typage l'impose).
- **WP-10 (coédition)** : le jeton de coédition viendra de `POST /missions/:id/collab-token` ; le client API le demandera avec `apiRequest` ; l'état de connexion de la coédition peut s'afficher dans l'en-tête de mission (`MissionFrame`). `myRole === null` signifie lecture seule dans l'interface (l'administrateur et un responsable non membre ont toutefois des droits côté API, voir PO-30).
- **WP-13 (Analyse)** : le tableau de bord attend les liens « Examiner », « Répondre », « Voir » vers l'espace Analyse (liste « À faire » aujourd'hui sans lien) ; la complétude par concept y est déjà calculée (`completeness()` donne aussi `pendingHypotheses`, `openQuestions` et les écarts par concept). Le mode expert doit y révéler ce que le PO définira [PO-91].
- Les composants de `packages/ui` ne dépendent ni de Next ni de l'API ; les nouveaux composants s'y ajoutent avec leur style dans `styles.css` (préfixe `pr-`).
- Tests E2E : `loginAndEnroll` (premier passage d'un compte, enrôlement par l'interface) et `loginWithDevTotp` (comptes déjà enrôlés) sont dans `e2e/tests/support.ts`.
